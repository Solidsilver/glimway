# Architecture review: Svelte UI and client libraries

Snapshot `f83ccde`. Scope: `src/App.svelte`, `src/ui/**`, `src/lib/**` (not the `api` types themselves), `src/content/**`.
Tools run: `svelte-check` (336 files, 0 errors, 0 warnings), `jscpd` (min 8 lines), `knip`.

## 1. Map

- **`src/App.svelte` (1,927 lines)** is the root. It does six jobs: the bus→store wiring (`wireBus`, 30 handlers, :190–380); the title screen (markup :1340–1440 plus 361 lines of CSS); the guest start/reset flow; the whole connected-play state machine (probe, world choice, origin, lease, take-over, party prompt, world move, logout, :470–925); global key ownership (:1015–1065); and DOM measurement for camera insets (:1077–1170). It also hosts every panel through a `panel` string union and an `{#if}` chain (:1288–1338).
- **`src/ui/` (57 files, flat).** It holds 39 components, six rune stores (`store.svelte.ts` `ui`, `home`, `villageUi`, `heldUi`, `inventory`, `papers`, `settings`), two actions (`focus.ts`, `sheet.ts`) and connected-mode glue (`account.ts` owns the one `api` client; `habitica-local.ts`). Panels take a `session` prop and read the non-reactive game models (`villageFor(session)`, `homesteadsFor`, `itemsFor`) through a local `version` counter that bus events bump.
- **`src/lib/`.** This is mostly pure, unit-tested rules shared with the Go server through `content/*.json` and the vector scripts: items, embers, gathering, homestead land, wilds, calendar, workshop and village. Beside them sits client IO: `api/client.ts`, `api/cache.ts` (IndexedDB), `save.ts`, `habitica/client.ts`, `presence-client.ts`, and `papers/library.ts`, which turns out to be a second HTTP client.
- **`src/content/`.** Copy objects (`signInCopy`, `worldCopy`, `inventoryCopy`, `CONTROLS`), lore data, the generated `papers-text.ts`, and some rules (`heirloomConditionMet`, `stageAtLeast`).

**Surprises for a newcomer:**
- Player-facing error copy for items, village and homestead lives in `src/game/*.ts`, not `src/content`.
- Some stores subscribe to the bus themselves (`held.svelte.ts`, `papers.svelte.ts`). The others are written by App's `wireBus`.
- App finds the HUD and touch-control boxes by querying other components' private class names (`.controls .belt .bslot`).
- No unit test touches `src/ui` or `App.svelte`. Only e2e covers them (53 specs, including screenshot specs).

## 2. Findings (ranked by payoff ÷ risk)

### F1. Panel boilerplate is repeated in 13 panels; the action runner in 9
**Evidence.**
- Thirteen panels repeat the same eight-line shell: `overlay sheet` + `use:sheet` + `use:focusTrap` + `panel-head` + `modal-close` + `panel-title` + `msg`. These are Character, Desk, GateShelf, Hearth, Inventory, Journal, Library, Mail, Menu, NoticeBoard, SilasShop, Woodpile and Workshop.
- Nine of them redeclare `busy`, `message: {text, kind}` and the "busy guard → await → busy = null → message ok/error" sequence by hand. Compare `WoodpilePanel.svelte:57–78` and `DeskPanel.svelte:48–60`. `InventoryPanel.svelte:302` already has the right helper (`act(id, run, okText)`), but only locally.
- Ten panels define `let version = $state(0)`, bus on/off pairs in `onMount`, and `void version` inside `$derived`. Examples: `DeskPanel.svelte:19–43`, `SilasShop.svelte:22–61`, `GateShelfPanel.svelte:28–78`.

**Change.**
- Add `src/ui/Panel.svelte`, taking `{id, icon, title, onClose, message, wide?}` and a `children` snippet.
- Add `src/ui/panel-state.svelte.ts` with two helpers. `actionRunner()` returns `{busy, message, run(id, fn, ok)}`. `busVersion(...events)` returns a reactive counter that subscribes in an `$effect` and cleans up on its own.

**Size:** M (mechanical, one panel per commit). **Risk:** low; behaviour is unchanged. **Guards:** `village`, `crafting`, `gifts`, `inventory`, `homestead` and `papers` specs, plus the screenshot specs for layout.

### F2. Shared panel CSS is copy-pasted (jscpd: 9.9% of component CSS duplicated)
**Evidence.** jscpd finds 664 duplicated CSS lines against 56 duplicated TS lines.
- Desk, Hearth, Woodpile and Workshop share 30–40-line blocks (`DeskPanel.svelte:109–140` ≈ `HearthPanel.svelte:117–148` ≈ `WoodpilePanel.svelte:134–165`).
- `.msg`/`.msg.error` is defined in 9 panels, `.lede` in 6, `.carried` in 5, `.batch` in 4 and `.tiny` in 9.
- `LeaverNotice`/`PartyPrompt` share 48 + 32 lines (`LeaverNotice.svelte:43–119`).
- `OriginChoice`/`WorldChoiceGate` share the `.option`/`.opt-*` choice card (about 90 lines), and part of it again in `WorldMove.svelte:318`.

**Change.**
- Promote `.msg`, `.lede`, `.carried`, `.batch` and `.tiny` into `app.css` next to `.panel-head`, which is already global.
- Promote the option card into the existing `gate-*` section of `app.css`.
- Make `NoticeCard.svelte` for PartyPrompt, LeaverNotice and LinkNotice.

**Size:** M. **Risk:** visual only. **Guards:** the `*-screens.spec.ts` screenshot specs and `polish.spec.ts`.

### F3. Five hand-written "is something on top?" lists in App.svelte
**Evidence.** Each list names a different subset of the same state:
- `uiState.panelOpen` (:997) has 7 terms.
- The `onKeyGlobal` guard (:1016 and :1029–1031) has 9.
- `promptClear` (:1174) has 14.
- `showPrompt` (:1236) has 6.
- `HomeBar hidden` (:1272) has 5.

For example, `confirmLogout`, `partyPrompt` and `leaverNotice` block the party prompt but don't set `panelOpen`. Any of these differences may be deliberate, but nothing records which.

**Change.** Add one `$derived` `layer` value that names the topmost thing (`'gate' | 'lease' | 'move' | 'panel' | 'confirm' | 'naming' | 'dialogue' | 'cinematic' | 'ending' | 'placement' | 'banner' | null`). Derive the five predicates from it, with a comment on each deliberate exception.

**Size:** S–M. **Risk:** medium, because it changes input gating. **Guards:** the `onboarding`, `party-worlds`, `homestead`, `talk` and `touch` specs. Before changing anything, write a table test of the current predicates.

### F4. The connected-play flow is about 450 lines inside App.svelte, with internal repeats
**Evidence.**
- `initServer`, `continueAccount`, `onSignedIn`, `openWorldChoice`, `chooseWorld`, `chooseOrigin`, `startAccount`, `settle`, `takeOverPending`, `afterMove`, `onMoved`, `onHere` and `logout` take up :470–925, alongside 14 `account*`/`gate`/`lease*`/`moving` state fields.
- Repeats inside that span:
  - `'Your sign-in ended. Sign in again…'` appears 3× (:600, :632, :784).
  - The `world-chosen` → `api.state()` → `onSignedIn` recovery appears 3× (:592, :619, :643).
  - The guest reset (`destroy` + `new Session(createNewGame())` + `hasSave=false` + `vitalsSource='demo'` + `importedProfile=null`) appears 3× (`showChoice`, `startFresh`, `startHabitica`, :933–968).
  - The "N min played" formatter appears twice (:160, :178).
  - The empty-`WorldRef` literal appears twice (:851, :868).

**Change.**
1. Make the in-file dedupes first: `signedOut()`, `resetGuest()`, `playedFor()`, `NO_WORLD`.
2. Then move the state machine into `src/ui/account-flow.svelte.ts`, a class with rune fields and the `api` injected, so it can be unit-tested with a fake client. App keeps the markup.

**Size:** S for the dedupes, L for the move. **Risk:** medium (lease and world-move edge cases). **Guards:** `connected.spec`, `party-worlds.spec` and `coop.spec`, plus new node tests against a fake `api`.

### F5. Two ways to mirror bus events into stores, plus duplicated mirrors and polling
**Evidence.**
- `held.svelte.ts:20` and `papers.svelte.ts:50` subscribe at module load. `ui`, `home` and `villageUi` are filled by App's `wireBus`, where about 20 of the 30 handlers are one-line copies like `ui.cinematic = p.active`.
- `InventoryPanel.svelte:84,92` keeps its own `heldKind` and `EV.held` subscription even though `heldUi` already exists.
- App polls `inventory.syncPack` every 1.5 s (:1006) and the guide pin every 1 s (:1212). `GuidesTab.svelte:19` adds a 1 s `tick` on top.

**Change.**
- Pick one pattern: each store exports `connect(): () => void`, which App calls in `onMount`. Move the plain mirrors into the stores and keep only the flow handlers in App (area/room banners, `village.open`, the library and shop openers).
- Make InventoryPanel use `heldUi`.
- Long term, have the game emit `EV.pack` instead of being polled. That part is cross-area.

**Size:** M. **Risk:** low–medium. **Guards:** `held`, `inventory`, `goal` and `quest` specs.

### F6. Error copy: three switch tables with an identical tail, kept in `src/game`
**Evidence.**
- `itemErrorText` (`game/items.ts:29`), `villageErrorText` (`game/village.ts:39`) and `homeErrorText` (`game/homestead.ts:121`) each end with the same `offline`/`superseded`/`busy`/`resolved`/`pending` cases, word for word.
- Several codes (`not-a-member`, `tier-required`, `shelf-not-empty`, `insufficient-materials`) get different wording in each table. That may be intended, but nothing records it.
- `ItemsResult` and `VillageResult` are the same type declared twice (`items.ts:26`, `village.ts:36`).
- `friendlyErrorCopy` in `ui/habitica-local.ts:98` is a fourth table.

**Change.** Add `src/content/errors.ts` holding a shared `transportErrorText(code)` and per-domain `Record<code, string>` maps. Add a single `Result<T>` in `lib/api/errors.ts`.

**Size:** S–M. **Risk:** low (copy moves as-is). **Guards:** a node test that every `ApiErrorCode` has wording in at least one map, plus the existing specs that assert refusal text.

### F7. Copy constants that are defined but unused while the code inlines the same text
**Evidence.**
- `TURNING_NOTICE_FORMAT` (`content/expansion-writing.ts:240`) goes unused while `lib/calendar.ts:26` hard-codes `` `Dark of ${wick}-wick — the outer Wilds will turn.` ``.
- `CHARTED_BY_FORMAT` (:186) goes unused while `game/wilds/entities.ts:503` writes `` `Charted by ${by}.` ``.
- `ECHO_UNSETTLED_EYEBROW` (`echoes.ts:187`) is never read.
- Dead functions: `hearthRecipe` (`lib/workshop.ts:67`) and `isModelInstance` (`lib/inventory.ts:311`).
- knip reports 69 unused exports overall. Most are only used inside their own file, so the fix there is just dropping `export`. Examples: `api/parse.ts` (14 parsers), `lib/items.ts` (10 constants), `lib/wilds/outer.ts` (5).

**Change.**
- Wire the two format constants in, or delete them.
- Delete the dead functions.
- Drop the unneeded `export`s in one sweep.

**Size:** S. **Risk:** very low. **Guards:** `tsc`, `svelte-check`, `npm test`.

### F8. `lib/papers/library.ts` is a second HTTP client with a compatibility shim
**Evidence.**
- `createRemoteLibrary` (:117) has its own `fetch`, timeout, JSON sniffing and error-code parsing, and it skips `api/queue.ts`, which is documented as "one in-order queue for every server call".
- Its header says the server contract is "not built yet — see .agent/REPORT.md" (:12), and it treats 404/405/501 or non-JSON as "no library on this server" (:156).
- The server now serves both routes (`server/internal/api/api.go:233–236`).

**Change.**
- Add `library()` and `libraryDonate()` to `lib/api/client.ts` with parsers in `parse.ts`.
- Delete the `unsupported` branch; keep the guest-local path.
- Fix the header.

**Size:** M. **Risk:** medium (donation ordering, offline). **Guards:** `papers.spec`, `papers-screens.spec`, the library unit test.

### F9. App measures child components through their private CSS classes
**Evidence.**
- App.svelte:1077–1170 (about 95 lines) queries `.hud > *`, `.controls .act`, `.controls .col`, `.controls .pad`, `.controls .belt .bslot` and `[data-testid="arrange"]`. From those boxes it sets `--hud-bottom`, `--dock-bottom` and `setPlayInsets`.
- Renaming a class in `Hud.svelte` or `TouchControls.svelte` silently breaks the camera insets.

**Change.** Move the code to `src/ui/play-insets.ts`. Children mark what should be measured with `data-inset="hud|cluster|ring|pad|arrange"`.

**Size:** S–M. **Risk:** medium (layout). **Guards:** `camera.spec`, `touch.spec`, `onboarding-layout.spec`.

### F10. Oversized components: some business logic, mostly CSS

**Change.**

**Size:** M. **Risk:** low–medium. **Guards:** `onboarding`, `embers` and `connected` specs.

**Size:** M (churn). **Risk:** low with `tsc`, but it conflicts with every open branch.

## 3. Keep as is (use these as the models)
- **Runes throughout.** No `svelte/store`, `export let` or `$:` remains, and `svelte-check` is clean. The class-with-`$state`-fields stores (`store.svelte.ts`, `settings.svelte.ts`) are the right shape.
- **`focus.ts` and `sheet.ts`.** One accessible modal behaviour (focus trap, return focus, touch sheet drag, dirty-field protection) shared by every panel.
- **The global `.panel-head`/`gate-*` classes and tokens in `app.css`.** F2 and F11 should extend these, not invent new ones.
- **Copy objects in `src/content`** (`signInCopy`, `worldCopy`, `inventoryCopy`). `content/controls.ts` is the best example: one source for the keyboard and touch lists, held together by `tests/world.test.ts`.
- **The pure `src/lib` rules with node tests and Go vectors** (49 of 54 test files cover lib or content), and `api/parse.ts` validating every server answer.
- **The generated `papers-text.ts`,** which carries a "do not edit" header and an `npm run papers` source.
- **Low TypeScript duplication** (0.25% by jscpd). The duplication problem is in markup and CSS, not logic.

## 4. Cross-area notes
- **Game.**
  - The bus is an untyped Phaser `EventEmitter` with six name objects (`EV`, `ITEMS_EV`, `VILLAGE_EV`, `HOME_EV`, `PAPER_EV`, `RESIDENT_EV`), so every handler states its payload type by hand (App's `pairs` is cast to `(...args: never[]) => void`). A typed `on<K>()` wrapper over one `Events` map would catch payload drift.
  - Error copy belongs in `src/content` (F6).
  - Emit a pack-changed event instead of having App poll (F5).
  - `KeyboardEvent.fsConsumed` is an ad-hoc key-ownership flag shared by `App.svelte:1036`, `WorldScene.ts:1231` and `homesteads.ts:1636`.
- **Layering.** `src/lib/wilds/{gen-v1,world-data,tangle}.ts` import from `src/game` (`textures`, `worlds`, `wilds/tangle-key`, `wilds/wilds-looks`), so the "pure, shared" lib depends on the runtime.
- **Server.** `/api/library` exists, so the client fallback can go (F8).
- **Tooling.**
  - There is no formatter or linter config. Semicolon and quote style differ by file (49 TS files in these dirs use semicolons, 33 don't), and long one-line styles show up in `lib/workshop.ts` and `lib/calendar.ts`.
  - `.ts` import extensions are needed where node tests load a module, so a formatter must not strip them.
  - knip is worth adding to `verify` once F7 has landed. It also reports `@fontsource-variable/nunito` and `@fontsource/pixelify-sans` as unused dependencies.
- **Open question for the owner.** `api/cache.ts:27` (`LEGACY_STORE` migration) and the pre-stamp branch in `inventory.svelte.ts:30` are compatibility code. They can go if no device from before the deploy (2026-10-06) still holds that data.

5. **F1, part 2 + F2:** `Panel.svelte` and the promoted panel CSS, checked against the screenshot specs. (M.)

7. **F3:** one `layer` derivation for overlay gating, with a predicate table test written first. (S–M.)
8. **F8:** move the library onto the API client and drop the 404 fallback. (M.)

After these: F4 part 2 (`account-flow.svelte.ts`), F9, F10 (`TitleScreen`), F11 and finally F14.
