# Architecture review: the Phaser game (`src/game/**`)

Snapshot f83ccde, 80 files, ~25k lines. Checks: `tsc` (clean), art tests, jscpd, madge, knip.
Literal copy-paste is low (jscpd: 0.34%); the duplication is **semantic**: the same idea re-written
in a new shape by another agent.

## 1. Map

**Boot** (`main.ts`, `scenes/BootScene.ts`): `startGame` puts the `Session` in `game.registry`.
BootScene preloads three pass manifests and the packed atlases. In `create()` it then runs an
**order-dependent stack of ~10 steps**: first it code-draws placeholders (`textures.ts`,
`commons-art.ts`), then it copies the delivered frames over the placeholder keys
(`commons-pass-install`, `runtime-art`, `items-pass`, `people`).

**Art pipeline**:
1. Source PNGs and a measured manifest sit in `assets/generated/<pass>/`.
2. `scripts/build-atlases.ts` bakes them in headless Chromium, driven by `atlas-plan.ts` (shared by
   the build, the runtime and the tests).
3. The output is committed to `public/assets/fingersnap/packed/` (8.6 MB).
4. At runtime, `density.ts` keeps dense frames (4 texels per world px) at world size by stretching
   the UVs.

Textures reach the GPU **8 ways**, among them exploded per-frame canvases, the people atlas,
boot-drawn and on-demand procedural textures (`area/props.ts:21`), and install copies over
placeholder keys.

**Areas**: there is one `WorldData` contract (`worlds.ts:110`), and the generic `area/*` layer
draws any of it (terrain, collision, props, foreground, exits, lanterns). The areas reach it five
ways:
- static builders in `worlds.ts`;
- `commons.ts`, which reads a module global for the gate count;
- `homeland.ts`, by prefix fallback;
- `cottage.ts`, whose registry entry is fake and which WorldScene calls directly;
- Wilds chunks, registered at runtime per epoch, which WorldScene must call
  `ensureWildsAreaKinds` for before building.

**Entities** (`entities/*`, 7.3k lines): each takes a `Phaser.Scene` plus a `XxxDeps` interface of
lazy closures. Nothing imports `scenes/`.

**WorldScene** (2,047 lines) builds areas, wires entities, routes input, arbitrates prompts, and
runs transitions, the camera, the Turning, "unmoored" and dialogue-action dispatch. `create()` is
**~600 lines (200–796)**, ~330 of them window dev hooks.

**Game ↔ UI** has six channels: the Phaser-emitter `bus` (~180 emits, **6 name registries** plus
raw literals); mutable singletons (`uiState`, `viewport`, `clock`); the scene writing the Svelte
store `ui.unmoored` (`WorldScene.ts:67`); direct UI imports of `game/session` (18 files), village,
homestead, items and papers; window globals (**`ConnectGuide.svelte:110,298` gates a real sync on
`window.__fsSafety`**); and constructor DI for `Link`.

**What a newcomer won't expect**:
- About half of `src/game` (~9.2k lines) never touches Phaser. It is the client domain/store layer
  (session, link, village, homestead, items, papers, wilds/store) that the UI is built on.
- `TILE = 16` lives in the 734-line `textures.ts`, and `src/lib/wilds/*` imports it from there
  (lib → game).
- `session.ts` imports Phaser for a single `Math.Clamp` (`:263`), so every UI file that imports the
  session pulls in Phaser, and no unit test can load the session.

## 2. Findings (ranked by payoff ÷ risk)

### F1. `npm test` is red at HEAD. S, no risk
`tests/atlases.test.ts:95` reports: "playtest1-pass/animations.json changed — stale packed
atlases". f83ccde added sources without a rebuild. The staleness check hashes whole shared
manifests (test:77-78, build:175-176), so any art drop that adds an *unused* frame breaks CI until
someone with cwebp and Chromium rebuilds. **Change:** rebuild now. Then hash only the records of the
frames in use (the test already computes `p1Used`). **Guard:** the test itself.

### F2. Dev hooks: 56 `__fs*` names, 24 shipped to production, one used by production. S–M, low risk
**Evidence:**
- 38 `(window as unknown as {...})` casts in 17 files, 20 of them in `WorldScene.ts:262–776`.
- Ungated examples: `__fsPlayer`, `__fsWorld` (the whole solid grid), `__fsSafety`, `__fsDebug`,
  `__fsHomes` (`homesteads.ts:174`), `__fsGround` (`terrain.ts:341`).
- No hook is ever deleted, so closures keep shut-down scenes alive.
- e2e runs the vite dev server (`playwright.config.ts:63`), so every hook can be DEV-only.

**The catch:** `ConnectGuide.svelte` decides whether sync is safe by calling `__fsSafety`. Gating it
would silently break sync.

**Change:** (1) a real seam for the safety check: `syncSafety()`, registered by WorldScene and
imported by ConnectGuide. (2) `src/game/dev-hooks.ts` with `expose(name, fn, scene)`: a no-op unless
`import.meta.env.DEV`, deleted on `shutdown`, typed by one `FsHooks` interface that `e2e/` shares.
(3) WorldScene's hook block moves to `scenes/world-dev-hooks.ts`, taking ~330 lines out of
`create()`.

**Guard:** the full e2e suite (it consumes every hook), plus `npm run build && grep __fs dist/` to
prove they're gone.

### F3. A Phaser-free bus, and one typed event registry. M, low–medium risk
**Evidence:**
- `events.ts:9` is `new Phaser.Events.EventEmitter()`. As a result every store (village, homestead,
  items, wilds/store, papers, residents, held, guide-pin, ~2k lines) imports Phaser, and **none of
  them has a unit test**.
- `tests/wilds-outer.test.ts:236` regex-parses `homestead.ts` as text because it can't import it.
- There are 6 registries and raw literals:
  - `'game:home-arrange'` (`HomeBar.svelte:138,147`, `homesteads.ts:162`) nearly collides with
    `HOME_EV.arrange = 'ui:home-arrange'`, which flows the other way;
  - `'game:clear-unmoored'` (`items.ts:231`, `WorldScene.ts:777`).
- The bus is untyped: `App.svelte:340` casts every handler to `never[]`, and `EV.mutationResolved`'s
  payload is re-declared inline in three places.
- `EV.sync`, `EV.goalLine` and `EV.dpad` have no users.

**Change:** a ~30-line typed emitter keyed by an `EventMap`, keeping Phaser's `(fn, ctx)`
signature so call sites don't change; fold the five `*_EV` objects into `event-names.ts`, delete
the dead names; drop Phaser from `session.ts`.

**Guard:** `tsc` (payload mismatches become compile errors), then new node tests for the stores.

### F4. Split WorldScene by responsibility. M (in steps), medium risk
Beyond the dev hooks (F2), WorldScene holds several self-contained subsystems:

- **The unmoored mechanic** (`:749–781`, `873–965`, plus the timers in `update` `:985–1023`): timers,
  flags, a camera veil and edges, and toasts. Its state lives in the **UI store**, which the scene
  mutates directly. Extract it to `entities/unmoored.ts`, with state crossing by bus event.
  - `update()` also calls `loadWilds()` twice per frame for the deep-Tangle check (`:987–991`).
- **The dialogue-action router** (`applyEmberAction` `:1477–1537`) does prefix matching on
  `home:`, `keep:return:`, `echo:settle:`, `heirloom:grant:`, `ada:oil` and `buy:`. It sits beside
  four server-call handlers (`returnKeepsake`, `grantHeirloom`, `marketBuy`, `giveAdaOil`) that all
  share the same shape: `notePosition`, call, `isActive` check, then an error toast or the payoff.
  - The refusal→text mapping is written twice: `:1523–1529` and `:1655–1667` share four identical
    strings.
  - Make a handler table `{prefix → handler}` in `scenes/world-actions.ts`, with one
    `withServer(call, onOk)` wrapper and one refusal-copy table in `src/content`. That table also
    replaces the offline/busy copies in items, village, homestead and wilds/entities.
- **Moves**: "set area/position, `saveSoon`, fade, restart on fade-out" is written out in
  `transitionTo` (twice), `enterRoom`, `playTurning` and `defeatRecovery`. Add one `moveTo()`.
- **Prompt arbitration**: `update` `:1053–1060` hand-ranks four proximity systems (see F5).
- **Portraits** (`emitPortraits` `:1387–1475`) is pixel trimming that belongs next to `density.ts`
  (`opaqueBox`). `homesteads.ts:790` has its own `artBox`.

The target is a scene of ~800 lines that wires modules and runs the frame loop.

**Guard:** e2e on transitions, defeat, the Turning and playtests. Do one extraction per PR.

### F5. Interaction: three registration paths, four proximity systems. M, medium risk
**Evidence:**
- Providers call `interactables.setDynamic(points, this)` themselves, and then WorldScene *also*
  calls `setExtra(provider)` (`:293–335`). Forget the second call and activation falls through to
  `dialogueFor`.
- `PaperPickups` is a third path, special-cased in `interactables.ts` at 66, 120, 220, 292 and 331,
  with its own `PaperInteraction` type. It looks like `onWorldRefresh` (`papers.ts:306`) removes the
  sprite but not the interaction point, which would leave a stale prompt (likely; verify).
- In `homesteads.ts`, one interaction id is switched on in six methods (`interactionList`,
  `markerOffset`, `label`, `verb`, `activate`, `onAction`).
- Reach is 34 in `interactables.ts:253`, 36 for gathering, and separate for wilds and the warden;
  the nearest-target loop exists four times (`interactables.ts:255,462`, `gathering.ts:145,334`).
- "Open a dialogue" (`uiState.dialogueOpen = true; sfx('open'); bus.emit(EV.dialogue)`) is written
  out at 5+ sites, and they have drifted: the keepsake merge *replaces* choices in
  `interactables.ts:334` but *appends* them in `homesteads.ts:1147`.

**Change:**
- An `Interactable` carries `{verb, label, markerOffset, activate}`.
- `setDynamic` is the only registration; papers moves onto it.
- Wilds, gathering and warden become providers, so one nearest-wins loop replaces the arbitration.
- Add one `openDialogue(payload)` helper.

**Guard:** e2e on interaction, papers, homesteads, gathering and the warden.

### F6. Split `homesteads.ts` (2,056 lines) and `enemies.ts` (1,143). M each, medium risk
**homesteads.ts:**
- It holds drawing (270–754), interactions and dialogue (755–1500) and its own placement editor
  with private keyboard and pointer input (1501–2039), plus 55 long prose strings.
- Its longest functions are `refreshPlacement` (122 lines), `talkToSilasNow` (119) and `activate`
  (107).
- Three different "still alive?" checks; `talkToSilas` sets `dialogueOpen = true`, then can return
  on `gone` without clearing it.
- `updateGuide` (504–526) re-implements `goal-guide.placeGlint` (213–245), but ignores
  `playInsets`, and it can show a second arrow to the same gate.
- **Split into:** `homestead-art`, `homestead-talk` and `homestead-placement`, with prose moved to
  `src/content`. Delete `updateGuide` in favour of GoalGuide.
- `workshopShort` (2048) is imported by `SilasShop.svelte` from this Phaser file; move it to lib.

**enemies.ts:**
- About 500 lines are the warden encounter (205–465, 557–620, 993–1143). The rest is creature AI.
- Split into `warden.ts` and `creatures.ts`, and move the inline contact reaches (532–551:
  12/14/15/18) into `ENEMY_TUNING`.
- The hero hit-tests enemies with its own loop in 4 places (`hero.ts:303,356,386,409`) and
  `projectiles.ts:45` does it a fifth time. Add `EnemySystem.hitCircle()`.

**Guard:** the combat, warden and homestead e2e suites. No unit test imports entities today.

### F7. One hash/RNG module, and TILE in a constants module. S–M, low risk (with one trap)
**Evidence:**
- About 11 private noise and hash copies:
  - mulberry32 at `worlds.ts:160` and `wilds/tangle-art.ts:73` (and two more in lib);
  - a lattice hash at `commons.ts:94` and `homeland.ts:102` (identical formulas), plus
    `ground-field.ts:104`, `tangle-art.ts:67`, `commons-art.ts:57` and `mill-art.ts:~49`;
  - `strHash` (`tangle-art.ts:83`) beside the canonical `fnv1a32` and `Rng` in `lib/wilds/hash.ts`.
  - The commons-art and mill-art copies have **drifted**: they multiply without `Math.imul`.
- `TILE` is hard-coded as `16` in `npc-routines.ts:67,179` and `ground-field.ts:200–218`, and
  aliased as `WILDS_TILE_PX`.
- Inline tile↔px math is written out ~170 times: 81× `tx*TILE+8`, 59× `(ty+1)*TILE` and 30×
  `` `${x},${y}` `` keys.

**Change:**
- `src/lib/tile.ts` holds `TILE`, `TERRAIN`, `tileCenter`, `tileFeet` and `tileKey`. This also fixes
  the lib → game imports.
- Route every copy through `lib/wilds/hash.ts`.

**Trap:** layouts and decor are seed-deterministic, so changing a hash moves trees. Unify by
*keeping each copy's exact formula* (named variants) unless a moved layout is acceptable. Never touch
`homestead-land.ts`, which is mirrored in Go.

**Guard:** `npm run vectors*`, plus a snapshot test of `buildArea()` grids for each static area
before and after.

### F8. Retire the superseded placeholder art. M, medium risk
**Evidence:** boot draws ~110 placeholder textures and ~70 are replaced moments later by delivered
frames (~55 frames then stored twice). Fully superseded or unreferenced: `mill-art.ts` (238 lines),
the `'terrain'` sheet (`textures.ts:374–481,651–658`), `hero1`, `lantern_off/on` (`:661,675`),
`createFingersnapTerrain`'s fallback (`expansion.ts:92–112`, which needs a texture never loaded),
and six mill animations never played (`items-pass.ts:205–224`). No test blocks `packed/`, so "the
placeholders are the fallback" (ASSETS.md:221,247) is untested.

**Decide first:** is a placeholder fallback still a product requirement? If **no**, delete the
superseded drawers, after moving into data the sizes that some placeholders supply
(`commons-pass-install.ts:96`, room walls at :225). If **yes**, add the e2e that blocks `packed/`.
**Guard:** `commons-pass.test` and e2e `atlases.spec`/screenshots.

### F9. One shape for the art passes, and shared draw helpers. M, low risk
**Evidence:** `commons-pass.ts`, `items-pass.ts` and `runtime-art.ts` declare identical
`Rect/Source/Animation` types (35–73) and repeat the frame-explode loop (137–145, 174–182, 108–117;
runtime-art throws where the others skip). Animation registration is written five times. Draw
helpers repeat: `rect` 5×, `px` 5×, `h01` 3×, make-texture-if-missing 4× (only one density-aware),

**Change:** one `art-pass.ts` (`preloadPass`, `explodeFrames`, `registerAnims`), one
`draw-kit.ts`, one `depths.ts`. **Guard:** the four art unit tests plus e2e texture hashes.

### F10. Make area builds explicit and deterministic. S–M, low risk
**Evidence:** `AreaKind.build` claims "Deterministic" (`worlds.ts:695`) but reads hidden state:
`commonsGateCount` (a module global set from `homestead.ts:330`), the `LandSource` injected by
`homesteadsFor()` (building `home:N` first silently uses the guest seed, which is why WorldScene
calls it at `:220`), and `gameNow()`. Season gates are hard-coded (`worlds.ts:390,397`,
`commons.ts:394`) although `content/gathering.json` declares them and `inSeason()` exists. The
cottage's registry entry is a fake `buildRoom(0, {19,11})`.
**Change:** `build(ctx: {gates, land, day})`; gate seasonal spots by `inSeason`; give the cottage a
real kind so WorldScene stops special-casing `this.room`. **Guard:** F7's grid snapshots and
`world.test`/`worlds.test`.

### F11. Store lifecycle and the materials mirror. S–M, medium risk
Village, homestead and items are per-session singletons (`xxxFor(session)`), but `wilds/store.ts`
uses module globals and needs `resetWilds()` from `App.svelte:847`. The Wilds keeps its own copy of
the materials balance, synced both ways (`store.ts:46`, `homestead.ts:556`). `homestead.ts` ↔
`village.ts` is a runtime import cycle. **Change:** `wildsFor(session)`; read materials from Village
only; pass the village into homestead. **Guard:** `wilds-runtime.test` and the Wilds e2e.

**Drifted comments:** the WorldScene header ("no networking yet"; presence is live), `worlds.ts:2`

**ASSETS.md:** it has no register entry for the playtest-1 pass (39 MB of sources shipping in

## 3. Keep as is
- **`XxxDeps` interfaces with lazy closures**, and narrow views like `HeroView`
  (`enemies.ts:133`). Entities never import the scene. Every new module should follow this.
- **`WorldData` → generic `area/*` renderer.** A new area is data plus a builder.
- **`atlas-plan.ts` as the single plan** for the build, runtime and tests, and `atlases.test`'s
  checks: plan vs built, the 4096 limit, the `public/` whitelist, and decoded-WebP texel equality in
  the build.
- **`density.ts`**: world-px frames with texel UVs, `TIE_BIAS`, and 2× on phones.
- **Phaser-free pure modules with node tests** (npc-routines, seats, placements, regions,
  `link.ts`, `presence-feed.ts`), and rules in `src/lib` with tests (gathering).
- `event-names.ts` split from `events.ts`; balanced `bus.on`/`off` on `shutdown`; key-`down`
  input instead of `JustDown` polling (`WorldScene.ts:363` explains why).

## 4. Cross-area notes
- **Server/link, possible bug:** `link.ts:791` `wildsMutation` mints `newKey()` *inside* the
  lambda that `exchange` retries. A stale-revision retry therefore goes out under a new idempotency
  key, and unlike `mutate` there is no lost-answer replay. `sync` and `wildsMutation` also skip the
  `'elsewhere'` failure action that `mutate` handles (`:575`). Four write paths (spend, sync, mutate,
  wilds) each copy the same guard prologue.
- **Server:** `wildsTileSize = 16` (`server/internal/api/wilds.go:565`) is used for every area, and
  `commons.tileSize` in `content/homestead.json:74` is validated but unused. No parity vector pins
  them to `TILE`.
- **UI:** `ConnectGuide` depends on `__fsSafety` (F2); `SilasShop` imports a Phaser entity file;
  seven UI files call `api` directly (including `App.svelte`'s world/invite writes), bypassing
  Link's revision and replay handling; `nudges.ts:4` and `interactables.ts:15` import from
  `src/ui`.
- **lib:** `lib/wilds` has a runtime import cycle (types → outer → gen-v1 → tangle → types) and
  imports from `game/` (F7).
- **Tooling:** each atlas rebuild commits ~8.6 MB (101 MB of sources, no LFS);
  `build-atlases.ts:464` empties `public/` before baking, so a failed run leaves it empty; encoder
  versions aren't recorded; ~316 KB of build-only manifest JSON ships to every client;
  `ground-heal.ts` (a build tool) should move under `scripts/`.

## 5. Proposed order
Each step is one reviewable PR.

1. **Green the tests.** Rebuild the atlases, and narrow the staleness hash to the frames in use (F1).
   Also delete the dead exports and fix the drifted comments listed in F12, which is pure deletion.
2. **Seam for sync safety, then `dev-hooks.ts`.** Make every hook DEV-only and clear it on
   shutdown, and move the WorldScene hooks into `world-dev-hooks.ts` (F2). This takes ~330 lines out
   of `create()`.
3. **Typed Phaser-free bus and one event registry.** Delete the dead names and the raw literals,
   and drop Phaser from `session.ts` (F3). Then add the first node tests for village, homestead and
   items.
4. **`lib/tile.ts` and the hash consolidation**, with `buildArea` grid snapshots taken *before* the
   change (F7).
5. **WorldScene extractions, one at a time:** unmoored → action router plus refusal-copy table →
   `moveTo` (F4).
6. **`openDialogue()`, then a single interaction registration.** Papers moves onto `setDynamic`,
   and interactables carry their own verbs (F5).
7. **Split `homesteads.ts`** into art, talk and placement; GoalGuide replaces `updateGuide` (F6).
8. **Decide the placeholder-fallback question**, then either delete the superseded art (F8) or test
   it, and collapse the passes onto `art-pass.ts`/`draw-kit.ts`/`depths.ts` (F9).
